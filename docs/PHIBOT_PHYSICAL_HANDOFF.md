# PhiBot Physical Experience Handoff v0.1

Status: **experimental / advisory-only / no tool authority**

This rung packages the governed PhiPie physical-experience advisory into a
portable PhiBot-facing handoff.

It is intentionally not a tool call, hardware command, safety instruction, or
authority grant.

## Purpose

The handoff lets a PhiBot receive:

- the bounded read-only investigation prompts generated by NBG;
- supporting memory IDs;
- supporting evidence IDs;
- uncertainty markers;
- the query physical-memory ID;
- a deterministic handoff fingerprint.

The receiving PhiBot may use that packet for reasoning and explanation.

It may not treat the handoff itself as permission to invoke a tool or change
physical state.

## Fixed recipient role

v0.1 targets:

```text
PHIBOT_PHYSICAL_OBSERVER
```

The role name describes the intended consumer. It does not grant privileges.

## Authority boundary

Every handoff fixes:

```text
grantsAuthority = false
actionAuthorized = false
mayInvokeTools = false
mayIssueHardwareCommands = false
requiresIndependentToolAuthorization = true
safetyPlaneUnaffected = true
```

The packet also carries empty arrays for:

```text
toolRequests
physicalCommands
```

Any receiver presented with non-empty values must refuse the packet.

## Allowed purposes

The handoff permits only:

```text
READ_ONLY_EVIDENCE_REVIEW
FORMULATE_OBSERVATION_QUESTIONS
```

Forbidden uses include:

```text
HARDWARE_ACTUATION
SAFETY_LIMIT_CHANGE
DIAGNOSIS_AS_FACT
CAUSAL_CLAIM_AS_FACT
MAINTENANCE_AS_REQUIRED_ACTION
```

## Independent authorization

A future PhiBot runtime may separately possess a read-only observation tool.

This handoff does not grant that capability.

If a PhiBot wants to act on an observation suggestion, the normal PhiOS /
runtime authority path must independently decide whether the requested tool is
available and authorized.

In other words:

```text
handoff suggestion
      !=
tool authorization
```

## Integrity

The packet carries an NBG-compatible deterministic fingerprint over the handoff
body.

That fingerprint detects accidental or ordinary in-band mutation of the packet
under the current NBG format. It is not claimed as production cryptographic
authentication.

The source physical memories and PhiPie episode journals retain their existing
provenance and integrity boundaries.

## Receive states

The NBG reference receiver returns:

```text
ACCEPTED_ADVISORY_ONLY
REFUSED
```

It never returns an authority-granted state.

## Non-claims

```text
recipient role != permission
handoff != tool grant
question != command
evidence != diagnosis
history != causal proof
advisory != physical authority
```

This creates the first clean agent-facing seam from PhiPie physical experience
through NBG while preserving the existing capability/authority firewall.
